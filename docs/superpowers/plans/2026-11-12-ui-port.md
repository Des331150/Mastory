# UI Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The ten locked prototype screens become the working UI of the real Django app, with every view, form and contract intact.

**Architecture:** The design language lands once in `base.html` + `reading.css` (tokens, fonts, masthead, shared components), then each screen's template is rebuilt to match its locked prototype's structure while keeping every hook the HTTP-seam tests read. The exam is the one behaviour change: one form, questions grouped in pages of three server-side, shown/hidden with Alpine.

**Tech Stack:** Django templates, one stylesheet (`reading.css`), htmx + Alpine (both already vendored), Google Fonts (Gabarito + Hanken Grotesk).

**Spec:** `docs/superpowers/specs/2026-11-12-ui-port-design.md`

## Global Constraints

- **Tests stay green.** The suite is `python3 .venv/bin/python manage.py test material.tests` — actually `.venv/bin/python manage.py test material.tests` from the repo root. 484 tests pass today; every task ends with its owning module green, and the final task runs the whole suite.
- **Test-read hooks survive verbatim.** Every class name and `data-*` attribute any test reads must still be on the page after the port: `spend-row`, `week`, `session`, `session-topic`, `session-when`, `session-length`, `session-state`, `session-action`, `log-entry`, `log-topic`, `panel behind`, `panel next-session`, `panel completion`, `panel session-log`, `standing-row`, `standing-complete`, `meter-fill`, `readiness-figure`, `weakest-topic`, `unweighed-note`, `topic flagged`, `error`, `question-prompt`, `stage <name>` (regex), and data attributes `data-calls`, `data-tokens`, `data-cost`, `data-kind`, `data-complete`, `data-mastery`, `data-state`, `data-students`, `data-total`, `data-mean`, `data-weighed`, `data-readiness`, `data-date`, `data-crossed`, `data-sittings`. Before editing a template, grep its test module for exact strings and hooks: `grep -n "class=\|data-\|In(\|NotIn(\|assertRegex" material/tests/test_<screen>.py`.
- **Asserted copy is not reworded.** Sentences the tests read stay byte-for-byte. New or reworded copy follows the unslop skill (read `/home/desmondpapaarhinful/.config/opencode/skills/unslop/SKILL.md`; rules 7, 9, 13, 14, 16, 17, 19 are the ones UI copy trips on most: no AI vocabulary, no "not just X but Y", no em dashes, no bold-label-colon lists, sentence case, straight quotes).
- **Design tokens** (from the locked signup screen, used by every task): ground `#f2f5f1`, ink `#17281f`, ink-soft (soften ink toward ground), green `#0e7c5b` reserved for progress, line `#d8ddd4` (line colour between ground and ink at low contrast), danger for failures. Fonts: Gabarito (display/headings), Hanken Grotesk (body), loaded via Google Fonts `<link>` with preconnect.
- **Every ported page renders clean at 1200px and 390px** — verify with the dev server (`http://localhost:8000/`) by fetching the page and checking the served HTML, plus one render check per screen for the human to eyeball.
- **No new front-end dependencies.** htmx and Alpine stay as they are.
- **Signup has nothing to port onto.** v0 has a hardcoded user (`material/users.py`); no auth template exists yet. The signup prototype's role in this port is only that it set the design language. The branch `t3/f69eb6be` carries real auth; its UI port is a separate plan when that branch lands.
- The dev server runs on port 8000 (restart if down: `nohup .venv/bin/python manage.py runserver 0.0.0.0:8000 > /tmp/opencode/devserver.log 2>&1 &`).

## Review Focus

- **A hook the tests read gets dropped in a rewrite.** The suite catches it if the module runs; every task's step list includes running the owning module, and the final task runs all 484. Pin: each screen task ends with its module green.
- **Asserted copy drifts during a rewrite.** The suite catches it. Pin: each task greps its test module for asserted strings before editing and re-reads them after.
- **The exam pagination breaks the one-form contract.** A student on page 3 must still be submitting the whole paper; every question input must exist in the served HTML regardless of page. Pin: Task 8's new tests assert one `<form>` and all inputs present in the HTML with no JS.
- **A page renders well on desktop but breaks at 390px.** The suite cannot catch layout. Pin: each task's render step checks the mobile width explicitly (the prototypes are the standard).
- **The cost page reads as a foreign page.** It gets prototypes first and a pick before its port. Pin: Task 10 does not start until the human picked a variant.

- [ ] **Step 1: Write the failing tests** in `material/tests/test_exam.py`:

```python
def test_the_paper_is_one_form_whatever_page_you_are_on(self) -> None:
    """The paper is handed in as one piece: every question input exists in
    the served HTML before any page is turned, so no answer depends on
    JavaScript having been pressed."""
    html = self.paper()
    self.assertEqual(flat(html).count("<form"), 1)
    inputs = re.findall(r'name="q-\d+"', html)
    self.assertGreater(len(inputs), 3)

def test_the_paper_says_answers_stay_until_the_whole_paper_is_handed_in(self) -> None:
    html = flat(self.paper())
    self.assertIn(
        "Nothing is marked or sent anywhere until you hand the whole paper in",
        html,
    )

def test_the_pager_counts_pages_of_three(self) -> None:
    html = flat(self.paper())
    self.assertRegex(html, r"Page 1 of \d+ · Questions 1–3 of \d+")
```

(Exact assertion style follows the file's conventions; the second pins the copy the prototype carries — read `prototypes/exam/01-sitting.html` for the exact sentence and pin that.)
